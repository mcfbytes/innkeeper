# Kernel usage in the LSCI scripts

Which kernels the INN and TSN scripts call, how often, with what arguments and what they do with the
result. Tables are generated by `tools/kernel_usage.py` (`.venv/bin/python tools/kernel_usage.py`) from
the decompressed resources in `work/res/<set>/<land>`; the prose is hand-written. Input for the
ScummVM kernel work: what to implement first, and in what shape. Related: `docs/lsci/interpreter.md`
(dispatch, handler table), `docs/protocol/ktsn.md` (the `TSN` kernel), `docs/lsci/script-format.md`.

Labels follow `docs/CONVENTIONS.md`: CONFIRMED means seen in code or data with an address or a
call-site count, INFERRED means a reasoned conclusion. Tables show the label of the sub-op meaning.

## 1. Findings

- CONFIRMED: the Feb-94 scripts contain 8,677 `callk` sites over 75 of the 93 kernels (0x00..0x5C).
  Eighteen static kernels are never called (listed under the per-kernel table). `IsObject`, `TSN`,
  `Graph`, `Display`, `DrawCel`, `Random` and `Animate` make up 63% of all call sites.
- CONFIRMED: there are **93** kernels, not 89. Kernels 0x59 `Palette`, 0x5A `Said`, 0x5B `Parse` and
  0x5C `SetSynonyms` are registered at start-up by the DLLs named in `LSCI.CFG` (section 3). Scripts
  call all four. `Palette` is on the boot path (46 calls, 45 of them in one class initialiser).
- CONFIRMED: only `Graph`, `Array`, `List`, `Seq`, `String`, `Memory`, `Sound`, `FileSystem`, `TSN`, `SID`
  and `Long` take a sub-op in argument 1. `Resource`, `Block`, `GetTime`, `Palette` and a few more take
  a mode or flag in argument 1 (section 5). `Display` takes tagged arguments instead (section 5).
- CONFIRMED: results are mostly ignored by the drawing kernels: `Graph` (75% of sites discard the
  accumulator), `Display` (79%), `DrawCel` (86%), `Animate` (86%) and `SetPort` (76%). Sites that
  consume the value: `IsObject` (89% tested), `GetPort` (96% stored), `ConfigStr` (97% stored),
  `ObjectNew` (85% stored), `CelWide` and `CelHigh` (about 77% in arithmetic), `Abs`, `Random`, `NumCels`.
- CONFIRMED: INN Feb-94 and Dec-93 call the same kernels and sub-ops. The visible differences are in
  call counts (`Random` +18 in hub, `Block` +5) and in `String` and `FileSystem`, which have 12 and 18
  sub-ops in both INN builds and 5 and 16 in TSN 2.1 (section 7).
- CONFIRMED: the start-up path of the game object reaches 31 or 32 kernels (a lower bound, section 8);
  the modules loaded at start-up call 71. INFERRED: `GetEvent` is also needed to boot, because the
  main loop reaches it through a receiver the analysis cannot resolve.

## 2. Method and caveats

- CONFIRMED: every script (`script.N`) and every type-31 module (`type31.N`) of every land of every set is
  decoded with `tools/lsci_bytecode.py`. The walk covers code items only (`tools/lsci_callflow.py`);
  method code, procedure code and exported procedures are all code items. A `callk` frame operand is the
  byte size of the arguments, so each call pops `argc + 1` words (`[argc][args...]`). A site is
  *verified* when the first popped word is the immediate `argc` the compiler pushed; every Feb-94
  site verifies except the `&rest` sites, which push a marker instead (`argc` shown as `n+`).
- CONFIRMED: argument provenance is the instruction that produced the pushed word. Sources: immediate,
  string (a `pushID` of a string item), object, class (`class n`), self, global, local, temp, param,
  property, kernel result, call result (call, callb, calle), send result, rest (the `&rest` marker),
  computed (arithmetic or logic on other values) and unknown. An immediate in a selector slot of
  `ObjectRespondsTo`, `ObjPropOffset` and `InvokeMethod` counts as a selector.
- CONFIRMED: result use is the first consumer of the accumulator after the call. Kinds: discarded
  (overwritten before use), tested (conditional branch), compared (`eq?` `lt?` ...), stored (into a
  global, local, temp, param or property), passed (pushed as an argument), computed (input to
  arithmetic), returned (`ret` with the value live) and receiver (target of a `send`). The percentages
  in the tables are shares of call sites with at least one use of that kind, so a row can add up to more
  than 100%. "unseen" means the path ended at a join the analysis does not follow.
- Limits (CONFIRMED by construction): the simulation is forward only. Backward branches are ignored,
  a merge of paths with different stack depths keeps the first stack, and sends are not followed into
  their targets. The call counts are those of decoded `callk` instructions; the provenance and result
  columns are heuristic and percentages are rounded down. The "typical callers" column names the method or
  procedure containing the call and the resource it lives in, with the number of sites in that owner.
- Counts are per resource set summed over its lands (`hub`, `SL`, `LL`). The same module is present in
  all three lands, so a shared module contributes up to three times the sites of one copy
  (for example 45 `Palette` calls are 15 per land).
- Pairing of sets and executables: `inn_feb94` with `LSCITV_inn_cd.EXE` (Feb-94), `inn_dec93` with
  `LSCITV_inn_v2317.EXE` (Dec-93), `tsn21` with `LSCITV_tsn21_031293.EXE` (TSN 2.1). `tsn_basic` is the
  single-disk TSN set (hub only); its executable is INFERRED to be the TSN 2.1 one.
- Class names such as `class_88` appear when the class has no name in the vocabulary. INFERRED role
  guide for the frequent ones: `class_88` = game controller (`init`, `play`, `newRoom`, `replay`,
  `showMem`), `class_21` = `Sound`, `class_2` = `File`, `class_3` = array wrapper, `class_61` = network
  message class (`send`, `rSend`, `register`, `lookup`), `Obj` = the base object of `type31.608`,
  `Collect` and `class_c`/`class_d`/`class_e` = list and iterator classes (`type31.612`/`613`).

## 3. Kernel numbering: the four DLL kernels

- CONFIRMED: the handler table of 89 far pointers at `DGROUP:1CE6` and the name table at `DGROUP:310A`
  are extended at run time by `AddKernel` (`16B1:0BFA`): `inc [1EC2]`, then handler and name stored at
  index `[1EC2] * 4`. `[1EC2]` is 0x58 in the file and is the bound checked by `callk` (`09C8:0538`).
  `docs/lsci/interpreter.md` section 3.5 has the DLL file layout and loader addresses.
- CONFIRMED: `NLNULL.DLL` registers `Said`, `Parse` and `SetSynonyms`. `GRAPH256.DLL` registers `Palette`
  and offers 30 graphics routines (`DrawCel`, `CelHeight`, `CelWidth`, `CelRect`, `NumLoops`, `NumCels`,
  `SaveBits`, `RestoreBits`, `InitGraph`, `EndGraph`, `FillRect`, `StdChar`, `OnControl`, `DrawPic`,
  `ShowBits`, `Line`, `LoadBits`, `SetPalInt`, `SetResPal`, `SetCLUT`, `DrawBrush`, `PalMatch`,
  `GetCLUT`, `GetPalette`, `RSetCursor`, `ScaleDrawCel`, `SetNewDim`, `GetCelPointer`, `GetMap`,
  `FillPoly`) that the built-in graphics kernels call through hook slots at `DGROUP:11D0 + 10k`.
  The ScummVM engine therefore needs `Palette`, `Said`, `Parse` and `SetSynonyms` as kernel entries
  0x59..0x5C and has to supply the graphics itself.
- INFERRED: load order GRAPH256 then NLNULL, which gives the numbers above. The script usage fits it:
  `Palette` takes 4 arguments with a first argument of 5 (45 sites in `type31.615`); `Said` (1 argument)
  is called from `InvI` and `class_2a`, `Parse` (3) from `class_26` and `SetSynonyms` (1) from `class_88`.
- INFERRED `Palette`: mode 5 is `Find(red, green, blue)` and returns a palette index (stored in a
  global at 97% of the sites); mode 1 is `SetFromResource(resource, flags)`, called once, in
  `script.1040` (the card game).

### 5.2 Display

- CONFIRMED: `Display` does not take a sub-op. Argument 1 is the text (string 19%, send result 30%, temp
  20%) and the rest are tag/value pairs. The handler dispatches on the tag through a jump table at
  `062F:0864` (file `0x9C34`) covering tags 100..120.
- INFERRED: the tags are SCI's `Display` ones (100 at, 101 mode, 102 color, 103 back, 104 style, 105 font,
  106 width, 107 save, 108 restore, 109 dispose). Immediates in 100..120 at the 415 sites: 100 x367,
  102 x360, 105 x364, 101 x149, 106 x218, 103 x88, 108 x48, 107 x35, 104 x12, 110 x3, 111 x1, 119 x1,
  120 x2. A coordinate that happens to equal a tag value is counted too, so the figures are upper bounds.
  Tags 110, 111, 119 and 120 are not decoded.

  histogram is in its section 9 and now agrees with this table (381 sites).

## 8. Priority for the ScummVM implementation

Ranking rules, in order: (1) kernels reached when the game boots, (2) kernels used by modules loaded at
start-up, (3) call volume, (4) number of different resources that call the kernel (breadth).

Boot analysis (two bounds, both from static call flow):

- Lower bound, CONFIRMED by construction: start from selector 0x1A (`play`) of the game object, export 0 of
  `script.000`, and follow `call`, `callb`, `calle` and sends whose receiver is `self` or a literal class.
  This reaches 31 or 32 kernels per land in Feb-94 and Dec-93, 31 in TSN 2.1 and 30 in `tsn_basic`. It
  misses sends to a receiver held in a variable, so `GetEvent` and the `DrawCel` family, which are
  certainly used once the first room draws, are absent.
- Upper bound: every resource reachable from `script.000` by `calle`, class loads, superclasses and
  `ModuleID`. It holds 71 kernels in each Feb-94 land. Resources loaded at start-up (LL / SL / hub):
  Feb-94 73 / 81 / 73, Dec-93 71 / 77 / 69, TSN 2.1 69 / 74 / 68, `tsn_basic` (hub) 65.

- LL: 31 kernels on the start-up path (Abs, Animate, Array, Block, ConfigStr, Debug, Display, DrawPic, GameIsRestarting, GetFarText, GetPort, Graph, HaveMouse, IsObject, List, Memory, ModuleDispose, ModuleID, ObjectFree, ObjectNew, Palette, Random, Resource, SID, SetCursor, SetDebug, SetPort, SetSynonyms, String, TSN, Wait); 71 kernels in the 73 resources loaded at start-up.
- SL: 32 kernels on the start-up path (Abs, Animate, Array, Block, ConfigStr, Debug, Display, DrawPic, GameIsRestarting, GetFarText, GetPort, GetTime, Graph, HaveMouse, IsObject, List, Memory, ModuleDispose, ModuleID, ObjectFree, ObjectNew, Palette, Random, Resource, SID, SetCursor, SetDebug, SetPort, SetSynonyms, String, TSN, Wait); 71 kernels in the 81 resources loaded at start-up.
- hub: 32 kernels on the start-up path (Abs, Animate, Array, Block, ConfigStr, Debug, Display, DrawPic, GameIsRestarting, GetFarText, GetPort, GetTime, Graph, HaveMouse, IsObject, List, Memory, ModuleDispose, ModuleID, ObjectFree, ObjectNew, Palette, Random, Resource, SID, SetCursor, SetDebug, SetPort, SetSynonyms, String, TSN, Wait); 71 kernels in the 73 resources loaded at start-up.

## 10. Open questions

- The `Display` tags 110, 111, 119 and 120 (13 sites) are not decoded; `Display` tags 100..109 follow SCI
  by name only.
- `Graph` 8, 9, 15 and `Memory` 4..6, 10 have INFERRED meanings; reading each case body to the end
  would settle them.
- The load order of the two DLLs is inferred. A test that registers the names in the other order would
  make `Said` 0x59 and `Palette` 0x5B, which the scripts contradict.
- The boot analysis is static; the real answer needs the ScummVM engine to run the first room and log
  the kernels it reaches.
- `tsn_basic`'s executable is INFERRED to be the TSN 2.1 build.

## 11. Reproducing this document

```
.venv/bin/python tools/kernel_usage.py                  # all sections
.venv/bin/python tools/kernel_usage.py --section subops # one section, repeatable
.venv/bin/python tools/ktsn_callsites.py work/res/inn_feb94   # every TSN site
```

The tools read `work/res/<set>/<land>` (not committed) and `work/exe/LSCITV_inn_cd.kernel.txt`, and
reuse `tools/lsci_bytecode.py` (decoder), `tools/lsci_callflow.py` (per-item stack analysis),
`tools/lsci_survey.py` (land walker, tallies, boot analysis) and `tools/lsci_kernels.py` (kernel and
sub-op tables).
